## 1. 스키마 버그 수정 (`typing` import 누락)

- **문제**: [app/schemas/meeting.py](../app/schemas/meeting.py)가 `List`·`Optional`을 import 없이 사용
- **증상**: pydantic이 검증 시 `List`를 못 찾아 `MeetingDraftRequest is not fully defined` → **모든 요청 처리 실패**
- **원인**: Python 최신 버전의 annotation 지연 평가로 import 시엔 안 터지고, 실제 검증 시점에 터짐
- **조치**: `from typing import List, Optional` 추가
- **검증**: 실제 요청이 200 응답으로 복구

## 2. 메시지 상한 상향 (30 → 50 → 200)

- **배경**: "하루 대화 드래그" 시나리오 검토 — 활발한 그룹 채팅은 30개를 쉽게 초과 → 422 하드 거절 위험
- **1차 결정**: 50으로 상향 + 정확도 회귀 테스트 병행
- **2차 결정**: Gemma가 읽을 수 있는 양 고려해 **200**으로 재상향
- **변경 파일**: [schemas/meeting.py](../app/schemas/meeting.py) `max_length=200`, README, 경계 테스트
- **검증**: 200개 접수(200) / 201개 거절(422) 경계 테스트 통과
- **참고**: 토큰/지연은 200개에서도 병목 아님 (한국어 채팅 200줄 ≈ 6천 토큰 수준)

## 6. 설계 결정 기록 — "null = 사용자 직접 입력"

- **결정**: AI가 null로 둔 항목은 사용자가 프론트/Spring Boot에서 직접 입력·지정
- **의미**: AI는 초안만 생성, 확정·저장·채움은 M1 범위 밖
- **주의점**: 진짜 위험은 null이 아니라 "그럴듯하게 틀린 값"(예: 병원 place 모호성)
- **기록**: 프로젝트 메모리 `null-fields-user-input.md`에 저장

## 7. 응답 구조 변경 — 단일 카드 → 카드 배열 (나들이 장소별)

- **요구**: 나들이에 장소가 여러 곳이면 **장소마다 카드 하나씩** 출력
- **설계**: 응답을 항상 **`list[MeetingDraft]`** 로 통일
  - 산책·병원 동행: 카드 1개
  - 나들이 + 여러 장소: 장소별 N개
  - 약속 없음: **빈 배열 `[]`**
- **변경 요약**:
  - [meeting_prompt.py](../app/prompts/meeting_prompt.py): 출력 스키마를 JSON 배열로, 규칙 10(나들이 장소별) 추가
  - [meeting_extractor.py](../app/services/meeting_extractor.py): `parse_json`이 카드 목록 반환(배열·단일객체 수용), `to_cards`(빈 카드 제거) 추가, `extract_meeting_draft` → **`extract_meeting_drafts`**
  - [routes/meeting.py](../app/routes/meeting.py): `response_model=list[MeetingDraft]`
  - README·테스트·골든 데이터셋 일괄 대응 (채점은 장소 정렬 정합 방식)
- **⚠️ 계약 변경**: 응답이 객체 → 배열. **Spring Boot는 `List<MeetingDraft>`로 수신하도록 수정 필요**, 빈 결과·502/504 fallback도 `[]`로 맞출 것
